# VpnPause

Сторож для Windows. Пока у адаптера `tun2` (Amnezia, tun2socks) есть маршруты VPN, выбранные программы работают. Маршруты пропали — эти программы и всё, что они запустили, замирают и ничего не отправляют. Маршруты вернулись — продолжают с того же места, без перезапуска.

Рабочая копия, которая сейчас запущена и стартует вместе с Windows, лежит отдельно:

`%LOCALAPPDATA%\Programs\VpnPause`

Запускается `VpnPause.exe`: отдельная программа со своим значком, не окно PowerShell. Рядом должны лежать `VpnPause.ps1` и `VpnPause.ico`.

Эта папка — сохранённый проект. Правка файлов здесь сама по себе работающий сторож не меняет. Чтобы подхватить правку: скопировать `VpnPause.ps1` в рабочую папку и перезапустить `VpnPause.exe`.

## Файлы

- `VpnPause.exe` — программа, которую видно в панели задач. Свой значок, не PowerShell.
- `VpnPause.ps1` — окно и слежение. Exe запускает этот файл.
- `VpnPause.ico` — значок окна и exe.
- `VpnPauseHost.cs` — исходник exe.
- `apps.txt` — полный путь к exe, одна программа на строку.
- `settings.txt` — имя адаптера VPN, строка `tunnel=tun2`.
- `vpn-pause.log` — журнал за 25 ноября 2026.
- `backup\2026-11-25` — снимок ps1, списка и журнала на момент первого сохранения.

## Как устроено

Туннель считается включённым, только если на выбранном адаптере есть оба маршрута `0.0.0.0/1` и `128.0.0.0/1`. Смена маршрута приходит сразу, запасная проверка — раз в 400 мс. Сейчас адаптер — `tun2`. Имя лежит в `settings.txt` и в окне, строка «Адаптер». Адрес сервера VPN программа не хранит и не проверяет: смена сервера в Amnezia ничего здесь не меняет. Другое имя адаптера нужно, только если VPN больше не поднимает `tun2`.

Совпадение программ:

- приложения из Microsoft Store — по семейству пакета и имени exe, поэтому новая сборка не выпадает из списка;
- Claude Code — любой `claude.exe` внутри `\claude-code\`, кроме копии внутри Ouroboros;
- остальные — по точному пути.

Если сторож убить, пока программы заморожены, при следующем старте с живым туннелем он их отпускает.

## Окно

Зелёная точка у часов — туннель есть, красная — программы на паузе, серая — слежение выключено. Крестик прячет окно, выход только через меню точки.

- Старт — слежение включено. Сейчас так и стоит. VPN пропал: ChatGPT, Claude и Claude Code замирают целиком, в том числе окно. Они не ходят в сеть и не показывают домашний IP. Короткий обрыв VPN они обычно не замечают: туннель вернулся — продолжают с того же места. Долгий обрыв сервер может оборвать сам, тогда после возобновления программа уже покажет ошибку связи.
- Стоп — заморозка выключена, замершие программы сразу отпущены. Дальше обрыв VPN их не останавливает.
- Из запущенных / Обзор / Удалить — список программ. На кнопках и списке есть подсказки.

Стоп не снимает запрет Wi-Fi в брандмауэре. Этот запрет висит всегда, пока правила не удалены. Поэтому даже после Стопа эти три программы по Wi-Fi не выходят: без VPN они получат ошибку сети, а не домашний IP. По VPN они ходят как обычно.

## Брандмауэр

Отдельно от паузы исходящие по Wi-Fi запрещены, `tun2` не задет:

- `VpnPause ChatGPT` — пакет `OpenAI.Codex_2p2nqsd0c76g0`
- `VpnPause Claude` — пакет `Claude_pzs8sxrjxfjjc`
- `VpnPause Claude Code` — текущий `claude.exe`

Обновить правила (нужен администратор):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Programs\VpnPause\VpnPause.ps1" -SyncFirewall
```

Остановить сторож и отпустить замершие программы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Programs\VpnPause\VpnPause.ps1" -Stop
```

Проверка заморозки на Блокноте: тот же файл с ключом `-SelfTest`.
